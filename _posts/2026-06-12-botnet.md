## 1. Botnet이란?

**Botnet** (robot network의 줄임말)은 멀웨어에 감염되어 공격자에게 **원격으로 제어**되는 기기들의 네트워크다. 기기 소유자는 대개 감염 사실을 인지하지 못한다.

- **Botmaster / Bot herder**: 봇넷을 구축하고 제어하는 공격자

---

## 2. Botnet 유형

C&C(Command & Control) 구조에 따라 세 가지로 분류된다. 구조에 따라 방어(takedown) 난이도가 결정되므로, 이 분류는 챕터 전체의 핵심 축이다.

### 2-1. Centralized Botnet

- **구조**: 모든 봇이 단일 C2 서버에 연결
- **프로토콜**: IRC, HTTP, HTTPS
- **장점(공격자)**: 관리·업데이트 용이
- **단점(공격자)**: **단일 실패 지점(Single Point of Failure)** — C2 차단 시 전체 붕괴
- **예시**: Zeus (Zbot), TorRat, Mirai, Emotet, Gafgyt (Bashlite)

### 2-2. P2P Botnet

- **구조**: 각 봇이 클라이언트이자 서버 역할 동시 수행
- **프로토콜**: 커스텀 바이너리 프로토콜
- **장점(공격자)**: 단일 실패 지점 없음 (높은 회복력)
- **단점(공격자)**: 구현 복잡, 지연(Latency) 발생
- **예시**: Storm, GameOver Zeus, Mozi

### 2-3. Hybrid Botnet

- **구조**: 중앙집중 + P2P 혼합
- **프로토콜**: HTTP/HTTPS + 커스텀 바이너리
- **장점(공격자)**: 유연성(Flexibility) + 회복력(Resilience)
- **단점(공격자)**: 구현 복잡, 동기화(Synchronization) 문제
- **예시**: Conficker, Torpig, ZeroAccess

### 핵심 트레이드오프 요약

| | Centralized | P2P | Hybrid |
|---|---|---|---|
| 관리 용이성 | ✅ 쉬움 | ❌ 어려움 | 중간 |
| 회복력 | ❌ 약함 | ✅ 강함 | ✅ 강함 |
| 구현 복잡도 | 낮음 | 높음 | 매우 높음 |

## 3. Zeus Botnet — 대표 사례

### 개요

| 항목 | 내용 |
|---|---|
| 활동 시기 | 2007 ~ 2010년대 |
| 유형 | Banking Trojan |
| 피해액 | $1억+ (수십억 달러 추산) |
| C&C 방식 | 중앙집중·HTTP 기반 |
| 주요 표적 | 은행 자격증명, 개인정보 |
| 전파 경로 | 피싱 이메일, Exploit Kit |

### Zeus 동작 6단계 라이프사이클

#### Step 1. 초기 감염 (Initial Infection)

피싱 이메일, 악성 첨부파일, Exploit Kit, **Drive-by Download**를 통해 전파한다. 사용자가 문서·소프트웨어 업데이트로 위장한 악성 파일을 실행하도록 유도한다.

**Drive-by Download**란 손상된/악성 웹사이트 방문만으로, 사용자 동의 없이 멀웨어가 자동 다운로드되는 공격이다. 브라우저·플러그인(ActiveX, Flash, Java) 취약점 또는 구버전 소프트웨어를 악성 JavaScript로 공격한다. 현대 시스템에서는 브라우저의 **Sandboxing·격리 메커니즘** 덕분에 거의 발생하지 않는다.

#### Step 2. 설치 및 지속성 (Installation & Persistence)

- 자기 자신을 숨겨진 위치(예: `%AppData%`)에 복사
- **레지스트리 항목 생성**으로 재부팅 후에도 실행 지속
- 보안 소프트웨어 무력화 또는 **Stealth 모드**로 탐지 회피

#### Step 3. 설정 파일 수신 (Configuration Retrieval)

하드코딩된 C&C 서버에 **HTTP POST** 요청을 보내 암호화된 설정 파일을 다운로드한다. 설정 파일에는 다음이 포함된다:

- 표적 은행 도메인 목록
- Form grabbing / Keylogging 지시
- 추가·백업 C&C URL

```ini
[ZeusConfig]
botnet     = "zbot_sample"
server     = "http://malicious-c2-domain.com/gate.php"
campaign_id= "ZEUScampaign01"
version    = "1.2.7"
urls = [
  "https://bankofexample.com/login",
  "https://secure-mail.com/signin"
]
grabbers = {
  "https://bankofexample.com/login": "POST",
  "https://secure-mail.com/signin": "POST"
}
```

#### Step 4. 자격증명 탈취 (Credential Harvesting)

브라우저를 감시해 표적 사이트에 입력된 자격증명을 가로챈다. 두 가지 기법을 사용한다:

- **Form Grabbing**: HTTPS 암호화 *전*에 폼 데이터 탈취
- **Keylogging**: 키 입력 기록 (DLL Injection으로 키보드 입력 후킹)

자세한 내용은 아래 [Form Grabbing 심화](#4-form-grabbing-심화) 섹션을 참고.

#### Step 5. 데이터 유출 (Data Exfiltration)

탈취 데이터를 암호화하여 또 다른 HTTP POST 요청으로 C&C 서버에 전송한다. 추가로 세션 쿠키, 브라우저 기록, 저장된 비밀번호, 인증서 파일도 업로드 가능하다.

#### Step 6. 원격 명령 실행 (Remote Command Execution)

C&C 서버를 주기적으로 **Polling**하며 새 명령을 수신한다:

- 설정 파일 업데이트
- 추가 멀웨어 다운로드·실행 (**Dropper** 역할)
- 자기 삭제로 흔적 제거 (**Kill Switch**)
- DDoS 공격 참여 (후기 Zeus)

## 4. Form Grabbing 심화

### 개념

웹 폼에 입력된 데이터(ID·PW·카드정보)를 **HTTPS 암호화 전에** 탈취하는 기법이다. **브라우저 프로세스 내부 (Application Layer)**에서 동작한다.

### Form Grabbing vs. Packet Sniffing 비교

| | Form Grabbing | Packet Sniffing |
|---|---|---|
| 동작 계층 | Application Layer (암호화 전) | Network Layer (암호화 후) |
| HTTPS 우회 | ✅ 가능 | ❌ 불가 (TLS/SSL에 막힘) |
| 탐지 난이도 | 매우 어려움 (브라우저 내부) | 상대적으로 탐지 용이 |

OSI 7계층에서 HTTPS(TLS/SSL) 암호화는 Presentation/Transport 계층 경계에서 적용된다. Form grabbing은 그보다 **위(Application Layer)**에서 데이터를 가로채므로 HTTPS를 무력화한다.

### 동작 방식

네트워크 전송을 기다리지 않고, **브라우저의 폼 제출 함수 자체를 후킹**한다.

후킹 대상 함수:
- Win API: `HttpSendRequestW`, `InternetWriteFile`
- JavaScript API: `form.onsubmit`, `XMLHttpRequest.send()`

구현 수단: **DLL Injection**

**DLL (Dynamic-Link Library)**은 Windows에서 여러 프로그램이 공유하는 재사용 코드·함수 파일이다(예: `user32.dll`의 `MessageBox`). **DLL Injection**은 실행 중인 다른 프로세스의 메모리 공간에 DLL을 주입하는 기법으로, 리눅스의 `LD_PRELOAD`와 유사한 개념이다.

### Form Grabbing이 위험한 이유 4가지

1. **HTTPS 우회** — 암호화 이전에 데이터 탈취
2. **탐지 어려움** — 브라우저 메모리 내부에서 발생
3. **정확함** — 정확히 입력값만 가로채므로 오탐 없음
4. **조용함** — 피해자에게 아무런 증상 없음

## 6. Botnet 대응 전략

### 중앙집중형 봇넷 대응

단일 실패 지점을 공략하는 것이 가장 효과적이다:

- **C&C 차단 / C&C Takedown**
- **IP/Domain Blacklisting** (Deny-listing) — 방화벽, ISP 레벨 필터링
- **Domain Sinkhole** — 악성 도메인 트래픽을 공격자의 진짜 C&C 대신 통제된 서버로 리다이렉트
- **C&C 서버 물리적 압수**

## 7. 방어가 어려운 이유 (4대 도전 과제)

방어가 있으면 공격자는 진화한다. 봇넷 박멸이 어려운 근본 이유를 살펴본다.

### ① P2P·Hybrid 구조의 회복력

단일 실패 지점이 없어, 일부를 무력화해도 다른 노드들이 계속 작동하며 네트워크를 재건한다.

### ② 규모와 분산

- 수천 ~ 수백만 감염 기기가 **전 세계에 분산** → 글로벌 협력 필요 (느리고 관료적)
- 인프라가 여러 국가에 분산 → 나라마다 상이한 법·집행력
- 감염 대상: PC뿐 아니라 **IoT 기기, 라우터, 모바일** — 대다수가 기본 보안 부재

### ③ 고급 회피 (Anti-analysis) 기법

| 기법 | 설명 |
|---|---|
| C&C 트래픽 암호화·난독화 | 통신 내용 분석 어렵게 만듦 |
| **DGA** (Domain Generation Algorithm) | 동적으로 C&C 도메인 생성 |
| **Fast-Flux DNS** | IP 주소를 빠르게 교체 |
| 프로그램 난독화·패킹 | 정적 분석 방해 |
| 동적 페이로드 로딩 | 동적 분석 방해 |
| **Anti-Sandbox** | 샌드박스 환경 탐지 후 비활성화 |

### ④ 정상 인프라 악용 (Abusing Legitimate Infrastructure)

클라우드·CDN·공개 DNS·Tor 등을 통신 은폐에 활용하고, 손상된 정상 서버를 **C2 Proxy**로 사용한다.

실제 악용된 공개 웹 서비스 사례(연구: "Hiding in Plain Sight"):
GDrive, Dropbox, Pastebin, GitHub, Telegram, Discord, Slack 등 — 정상 트래픽에 섞여 탐지를 어렵게 만든다.

## 8. 회피 기법 심화

### DGA (Domain Generation Algorithm)

날짜·시드값 등을 기반으로 알고리즘적으로 **수천 개의 도메인을 자동 생성**해 C&C를 찾아 연결하는 기법이다.

```
예시
base64(YYYYMMDD) → a9k38.com
```

공격자는 생성될 도메인 중 **일부만 미리 등록**하면 된다.

방어를 어렵게 만드는 이유:
- 도메인이 동적 생성 → DNS 블랙리스팅 무력화
- 수천 개의 백업 도메인 → 인프라 전체 차단 사실상 불가능

### Fast-Flux DNS

하나의 도메인에 연결된 **IP를 극히 빠르게 교체**해 C&C 인프라의 회복력을 높이는 기법이다.

- **TTL(Time-To-Live)을 극단적으로 짧게** 설정 (예: 60초)
- 연결된 IP가 매우 자주 변경됨
- DNS Zone File에서 A 레코드(도메인-IP 매핑)의 TTL을 짧게 두는 방식으로 구현

### IP/Domain Blacklisting의 한계

봇 바이너리에 C&C IP/도메인이 **하드코딩**되어 있으면, 정적 분석만으로 쉽게 식별·차단된다. 공격자들이 DGA와 Fast-Flux DNS로 진화한 배경이 바로 이것이다.

## 9. 실제 Takedown 사례

### Case 1. Emotet (2021년 1월) — 중앙집중형 Takedown

**참여**: FBI, Europol, 한국 경찰청 등

| 특성 | 내용 |
|---|---|
| C&C 구조 | 중앙집중(Centralized) |
| 유형 | Banking Trojan + Dropper |
| 배포 멀웨어 | TrickBot, QakBot, Ryuk Ransomware |
| 비즈니스 모델 | **Botnet-as-a-Service** |
| 회피 기법 | DGA + Fast-Flux + Tiered C&C |
| 감염 규모 | 130만+ 기기 |

**Operation LadyBird 진행 과정:**

```
1. C&C 인프라 장기 모니터링·식별 (100개 이상)
2. C&C 서버 물리적 압수 (Europol)
3. 압수한 서버를 Sinkhole로 전환
4. Sinkhole 서버를 통해 감염 봇에 "제거(Removal)" 업데이트 배포
   → 능동적·공격적 Takedown 전략
```

Emotet은 2021년 말 부활했다.

### Case 2. GameOver Zeus (GOZ) (2014년 6월) — P2P/Hybrid Takedown

**참여**: FBI, Europol, UK NCA 등

P2P 구조이므로 단순 서버 압수로는 불충분하다. 더 정교한 접근이 필요했다.

```
1. P2P 프로토콜 분석 → 감염 노드를 모방한 Sinkhole Peer 구축
2. 대량의 Sinkhole Peer를 봇넷에 삽입
3. Sinkhole Peer가 다른 봇에 가짜 설정 파일 배포 (공격 명령 없음)
4. DGA 분석 후 생성될 C&C 도메인 선점
5. C&C·프록시 서버 물리적 압수
```

## 전체 흐름 정리

```
봇넷 구조 (3종)
├── Centralized  →  단일 실패 지점  →  방어 상대적으로 용이
├── P2P          →  분산·회복력 높음  →  방어 어려움
└── Hybrid       →  둘의 절충        →  방어 가장 어려움

Zeus 6단계 라이프사이클
감염 → 지속성 → 설정수신 → 자격증명탈취 → 유출 → 원격명령
                                  ↑
                    Form Grabbing (HTTPS 우회) + Keylogging (DLL Injection)

방어 전략 = 단일 실패 지점 공략
  → C&C 차단 / Blacklisting / Sinkhole / 물리 압수

공격자 진화 (회피 기법)
  → DGA (동적 도메인 생성)
  → Fast-Flux DNS (동적 IP 교체)
  → 정상 인프라 악용 (C2 Proxy, 공개 웹 서비스)
  → Anti-Sandbox, 난독화, 동적 페이로드

실제 Takedown
  → Centralized: Sinkhole + 물리 압수 + 능동적 봇 제거 업데이트 배포 (Emotet)
  → P2P/Hybrid: Sinkhole Peer 삽입 + DGA 도메인 선점 (GameOver Zeus)
```
